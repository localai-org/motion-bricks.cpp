# Using SOMA

SOMA generates human motion between poses. It uses the same FFI-friendly C API
as G1: include `<motionbricks/inference.h>` and link `motionbricks`. There is no
separate SOMA handle family or header. The browser demo can offer both models;
see [demo setup](DEMO.md). The [API guide](API.md) explains linking and ownership.

## Prepare the model

Fetch the pinned upstream weights and convert them to a SOMA GGUF bundle using
[`reference/fetch_soma.py`](../reference/fetch_soma.py) and
[`scripts/convert_soma_to_gguf.py`](../scripts/convert_soma_to_gguf.py).
See the [reference setup commands](../reference/README.md) for the Python
preparation environment. Python is not required by the native runtime.

## Load and generate

1. Create `mb_runtime_options`; set model kind to `MB_MODEL_SOMA` and choose CPU,
   Vulkan or auto. Call `mb_model_load`. The default kind remains `MB_MODEL_G1`.
2. Create `mb_inference_request`; configure its skeleton using
   `mb_inference_request_set_skeleton`. Setters copy their input arrays.
3. Supply four context frames and one to four target frames using
   `mb_inference_request_set_boundary_transforms` (boundary 0 and 1).
4. Call `mb_model_infer` to obtain an ordinary `mb_motion`. The result contains
   endpoint-corrected motion at 30 Hz, typically 18–58 frames.
5. Read frame/joint counts and local rotations using the common motion getters.
   `mb_motion_get_local_translations` supplies per-joint translations, including
   the root. These vary with SOMA motion; do not substitute fixed bone offsets.
6. Free the motion, request, model and options with their matching free functions.
   Serialize calls sharing a model or request. Motion data outlives both.

Here is the central call sequence. Check **every** status; `error` contains the
specific reason on failure. The arrays shown as inputs come from your skeleton
and controller; they are not generated by this example.

```c
mb_runtime_options *options = NULL;
mb_model *model = NULL;
mb_inference_request *request = NULL;
mb_motion *motion = NULL;
char error[1024];
#define CHECK(call) do { if ((call) != MB_OK) { fprintf(stderr, "%s\n", error); goto cleanup; } } while (0)

CHECK(mb_runtime_options_create(&options, error, sizeof error));
CHECK(mb_runtime_options_set_model_kind(options, MB_MODEL_SOMA, error, sizeof error));
CHECK(mb_runtime_options_set_device(options, MB_DEVICE_VULKAN, error, sizeof error));
CHECK(mb_model_load(bundle_path, options, &model, error, sizeof error));
CHECK(mb_inference_request_create(&request, error, sizeof error));
CHECK(mb_inference_request_set_skeleton(request, joints, parents,
    reference_xyzw, (uint64_t)joints * 7, model_to_pose, 30,
    right_leg, left_leg, error, sizeof error));
CHECK(mb_inference_request_set_boundary_transforms(request, 0,
    context, (uint64_t)4 * joints * 7, error, sizeof error));
CHECK(mb_inference_request_set_boundary_transforms(request, 1,
    target, (uint64_t)target_frames * joints * 7, error, sizeof error));
CHECK(mb_model_infer(model, request, &motion, error, sizeof error));
/* Inspect/render motion here; borrowed getter buffers live until motion_free. */
cleanup:
mb_motion_free(motion);
mb_inference_request_free(request);
mb_model_free(model);
mb_runtime_options_free(options);
```

## Skeleton and pose layout

Transforms are frame-major `[frames, joints, 7]`: local XYZ metres followed by
quaternion XYZW. Both boundaries use a common Y-up model coordinate system.
Quaternions must be normalized (squared norm within .02 of one); all values must
be finite and within ±10000. The skeleton has 30–256 joints in parent-before-child
order, with Hips at index zero and parent -1. RightLeg and LeftLeg supply heading.

The mapping contains 30 unique indices into your output skeleton, in this order:

```text
Hips Spine1 Spine2 Chest Neck1 Neck2 Head Jaw LeftEye RightEye
LeftShoulder LeftArm LeftForeArm LeftHand LeftHandThumbEnd LeftHandMiddleEnd
RightShoulder RightArm RightForeArm RightHand RightHandThumbEnd RightHandMiddleEnd
LeftLeg LeftShin LeftFoot LeftToeBase RightLeg RightShin RightFoot RightToeBase
```

Extra joints retain their reference local transforms. Replacing the request's
skeleton clears its boundaries; a rejected setter leaves its previous state
intact. SOMA has no fixed output skeleton on `mb_model`: its joint metadata
getters return an informative error. Keep your skeleton metadata and use the
motion's joint count for output dimensions.

## Chaining and optional controls

Feed the final four corrected local transforms into the next context. Adjacent
clips share an endpoint; emit it only once. `MB_MOTION_LOCAL_TRANSFORMS` and
`MB_MOTION_WORLD_TRANSFORMS`, read using `mb_motion_copy_field`, provide interleaved
transforms. NULL/zero queries the required float count. `MB_MOTION_CONTACTS`
provides four contact values per output frame. `MB_MOTION_FEATURES` is diagnostic
raw output `[4*tokens,366]`, before endpoint correction.

All durations are enabled by default. Use the existing
`mb_inference_request_set_mask` with `MB_INFERENCE_DURATIONS` and eleven 0/1
values to allow durations of 6–16 tokens. At least one must be enabled.
`mb_inference_request_set_heading` sets canonical heading in radians, atan2(x,z).
The default is zero (+Z); NVIDIA's interactive controller uses pi/2 (+X).

FP32 is the default. `mb_inference_request_set_precision` opts into other
arithmetic profiles defined in `inference.h`. The qualified Vulkan mixed-FP16
profile requires RTX 5070 Ti, driver 595.71.05, the SOMA Vulkan build overlay and
exact normalization scales. Unsupported hardware/configurations return errors.
CPU SM120 is diagnostic arithmetic emulation and needs calibration tables via
`mb_model_set_arithmetic_calibration`; it is not FP16 acceleration.

The FP16 recorded-input suite passes all 82 events, but closed-loop FP16 playback
still exceeds the strict rotation tolerance. Use FP32 for the interactive demo.
See [validation scope and reproduction](../reference/README.md).

## Invalid configurations

Functions return `mb_status` plus a bounded, caller-owned error buffer. Failed
inference clears its motion output; a failed batch clears every output slot.
Examples of errors include duplicate mappings, invalid parent order, non-unit
quaternions, missing boundaries, empty duration masks and unsupported precision.

SOMA uses deterministic pose argmax and derives its feature masks from pose
boundaries. Explicit seed/sampling overrides and non-duration feature masks are
rejected at inference, including setting them to their default values. Raw G1
feature inputs cannot be mixed with retargeting configuration. G1 rejects SOMA
retargeting/precision settings. The existing `mb_agent`/style controller currently
supports G1; SOMA callers use `mb_model_infer`, as the shared demo controller does.
Unsupported operations fail explicitly rather than silently ignoring settings.

`mb_model_infer_batch` also accepts SOMA requests, executing them independently
through the same validated path. This is not a claim of accelerated batching.
